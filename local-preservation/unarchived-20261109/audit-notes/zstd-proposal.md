# Proposed Zstandard contract

Pending independent review, compatibility tests, and allocation proof on supported targets. Compression level remains a benchmark result.

Candidate runtime: `zstd-safe` 8.2.0 with locked `zstd-sys` 2.1.2+zstd.1.5.7. Use vendored source with offline builds, avoid system-library selection, legacy support, dictionaries and multithreaded compression. Verify feature unification and build environment. RustSec advisory https://rustsec.org/advisories/RUSTSEC-2026-0406 affects older safe bindings.

Read at most 64 MiB including the fixed 32-byte container header. Check magic, little-endian versions and codec, checked lengths and exact input size, and the 64 MiB expanded limit. A checked RFC 8878 frame-header parser verifies ordinary Zstandard magic, descriptor and header lengths, checksum flag, dictionary ID, frame content size when present, and window size at most 32 MiB before allocating a decoder window. A zero or absent dictionary ID cannot prove an encoder never used a hidden dictionary; never supply one and reject streams that need it. `zstd_safe::find_frame_compressed_size` must equal the whole payload; reject concatenation, skippable frames and trailing bytes. Cross-check declared content size through the binding.

Use a fresh DCtx, set `WindowLogMax(25)`, and stream into a fixed scratch buffer and bounded sink. Stop at the first completed frame and require exact compressed and expanded counts. A one-byte probe after filling the declared output catches extra output. Reject no progress, premature end and checksum errors. Separate unsupported versions/codecs, malformed input, resource limits and I/O.

Writer uses a fresh single-thread context, no dictionary, content size and checksum enabled, window log 25, exact pledged source size, a fixed chunking pattern and the benchmark-selected compression level. Validate the output frame. Source-level analysis of vendored zstd 1.5.7 suggests a streaming buffer request ceiling of 33,947,712 bytes plus the target-specific DCtx allocation; this needs an independent source audit, actual target sizes and instrumented validation. The aggregate budget also includes container, message, domain, image and temporary allocations.

Required evidence: fuzz and compare the header parser against upstream parsing, check all header boundaries, checksums, dictionary IDs, frame concatenation and output lengths, and compare complete golden bytes on supported platforms. A pinned library version alone does not prove deterministic encoding.

Sources: https://www.rfc-editor.org/rfc/rfc8878, https://github.com/facebook/zstd/blob/v1.5.7/lib/decompress/zstd_decompress.c, https://docs.rs/crate/zstd-safe/8.2.0/source/src/lib.rs, https://docs.rs/crate/zstd-sys/2.1.2%2Bzstd.1.5.7/source/build.rs.

## Independent review corrections

Sol medium rejected the first proposal until these rules and their implementation are reviewed. The descriptor's bits 7..6 select content-size width, bit 5 selects single segment, bit 4 is unused, bit 3 is reserved, bit 2 indicates checksum, and bits 1..0 select dictionary-ID width. Reject bit 3. Ignore bit 4 when reading and write it as zero. Dictionary widths are 0, 1, 2, 4 bytes. Content-size widths are `single_segment ? 1 : 0`, 2, 4, 8 bytes. Decode little-endian; add 256 for two-byte content size. A single-segment frame has no window descriptor and its window equals content size. Otherwise compute `base = 1 << (10 + (window_descriptor >> 3))` and `window = base + (base / 8) * (window_descriptor & 7)` using checked arithmetic and bounds. Require checksum. Permit absent and explicitly zero dictionary IDs, reject nonzero IDs, provide no dictionary or prefix, and reject decoding failures. Do not claim that successful decoding proves encoder provenance.

Use `default-features = false`, explicitly select vendored compilation, verify unified features exclude system pkg-config, legacy, dictionary builder, and multithreading, and reject `ZSTD_SYS_USE_PKG_CONFIG` whenever set, including empty. Confirm exact build behavior and preserve offline builds. Use `DCtx::try_create`, initialize once, set and check `WindowLogMax(25)`, and do not reset the parameters. Require end-of-frame zero, complete input consumption, exact output count and checksum validation. Scratch size is 65,536 bytes; use an extra-byte probe without appending it. Use a fresh `CCtx` and explicit streaming operations that do not reset configured settings. Bound writer output and choose a fixed chunk size before implementation.

The buffer figure assumes a fresh context, ordinary frame, buffered output, no dictionary and no legacy decoding. Add target-specific context request, scratch, sink and simultaneous buffers. Tests must independently exercise descriptor unused/reserved bits, every content-size and dictionary-width form, fractional windows around 32 MiB, checksums, unsupported frames, truncation, and exact-output completion. Full runtime pin and implementation remain unapproved.

## Writer and build follow-up

Proposed writer: `CCtx::try_create`, check each parameter call in this order: selected compression level, window log 25, content size flag, checksum flag, dictionary ID flag false, and zero workers if exposed in the chosen feature set. Set pledged input length. Feed fixed 65,536-byte slices with `compress_stream2` and `ZSTD_e_continue` until consumed, then call it with empty input and `ZSTD_e_end` until it returns zero. Use 65,536-byte output scratch, a checked progress rule, and at most 64 MiB minus 32 bytes of payload. At the cap, use a one-byte probe and return typed resource failure if more output appears. Verify final frame header and size. The compression-level choice remains benchmark-dependent. Verify all API availability in the exact feature set before accepting this contract.

Decoder: `DCtx::try_create`, checked `init()`, checked `set_parameter(WindowLogMax(25))`, then `decompress_stream` only. Map context allocation and parameter failures to typed errors. Check frame completion before no-progress, continue through checksum validation after declared output fills, and use a one-byte probe without appending.

A Tuiscotti build script must reject `ZSTD_SYS_USE_PKG_CONFIG` whenever present, even empty, with `rerun-if-env-changed`. Use exact direct constraints for both runtime and sys versions. In the supported workspace, pin vendored source and check the resolved dependency graph and features. Cargo can unify additive features from other dependencies: review their actual effects and document supported downstream feature/version verification. Independent review found that deliberately patched dependencies, Cargo links overrides, and arbitrary link substitution are outside the supported reproducible build boundary. A feature-tree check in this workspace alone must not be described as enforcing downstream configuration.

The safe binding's `NbWorkers(0)` parameter is available with multithreading disabled. A local compile/run probe exercised the proposed parameter and streaming calls with zstd-safe 8.2.0, vendored zstd-sys 2.1.2, and no default features. Retain the exact probe commands and wrapper evidence before treating this as verified. Additive Cargo features remain supported only where their source-selection and runtime effects have been audited.

## Independent sub-contract verdict

Sol medium accepted this Zstandard design as implementable after the corrections above. Set `NbWorkers(0)` unconditionally. Audited additive-feature support qualifies the earlier blanket exclusion language. This verdict does not cover aggregate allocation accounting, source/package verification, adversarial implementation tests, benchmark-selected compression level, or cross-platform byte identity. The local probe exercised setup and compression calls but did not prove decompression round trips.
