## Independent review corrections

The focused Sol medium review rejected the initial digest contract. Add `SampleError::DigestProjection { source: serde_json::Error }` for each fallible private snapshot or contract serialization step. Its display names the state-digest projection, its `Error::source` returns the serde error, and `sample_code` maps it to `INVALID_SAMPLE`, preserving the prior wildcard classification. Image errors remain image or resource errors.

Proposed `BinaryFormatError` is public, non-exhaustive and has `Header { detail: &'static str }`, `Wire { offset: usize, detail: &'static str }`, `Frame { detail: &'static str }` and `Codec { source: Box<dyn Error + Send + Sync + 'static> }`. `SampleError::InvalidFormat` carries it as its source. Codec errors retain their source but never become filesystem `IO`. Keep details bounded. Unsupported container/message/logical versions and codecs use distinct typed variants mapped to `UNSUPPORTED_SCHEMA`; retain the current `UnsupportedContract` classification as `INVALID_SAMPLE`. Review malformed-varint versus arithmetic overflow, narrowing versus limits, and PNG limit classification before adopting the table.

Private contract serialization writes `blink: null` for None, `false` or `true` for present values, and cursor phase as lowercase `shown` or `hidden`. Preserve original float types and font order. Capture old exact contract projection bytes and state digests for signed zero and each blink presence using transient old-reader fixtures. Synthetic old-reader samples do not imply they pass the approval re-render check. Binary-side noncanonical acceptance, evidence bytes, and executable error/source-chain tests remain open.

## Specific boundary decisions

A malformed numeric varint (more than 10 bytes, invalid tenth byte, continuation on the tenth, truncation or value overflow) is `InvalidFormat::Wire` and `INVALID_SAMPLE`. Decode a valid u64 before applying limits. A valid declared size/count above its explicit ceiling is `RESOURCE_LIMIT`, even if the payload is incomplete; an in-limit but truncated payload is `INVALID_SAMPLE`. Valid claims whose checked size, count or budget aggregation overflows are resource errors, without fabricating a saturated value. A narrowing violation such as index 256 or cell width 65536 is `INVALID_SAMPLE`, except where a separately documented resource ceiling is exceeded first. Zero dimensions and invalid domain invariants remain invalid samples.

Proposed public non-exhaustive `ResourceLimit` fields: `resource: &'static str`, `claimed: Option<u64>`, `limit: u64`, and `source: Option<Box<dyn Error + Send + Sync + 'static>>`. `Some(n)` is an exact observed claim; `None` means checked arithmetic overflow or an upstream limit report without an exact claim. Display names overflow or unknown claim. The limit uses the named resource's units; source chaining preserves a decoder cause. On a platform where a valid u64 cannot fit usize, return resource error with the exact length and representable ceiling. Existing TooLarge, DimensionTooLarge and RgbaTooLarge variants retain `RESOURCE_LIMIT`. Explicit PNG allocation/dimension limit errors use `RESOURCE_LIMIT`; invalid PNG data, checksums, color and image digest remain `INVALID_IMAGE`. Ambient OOM recovery is not promised.

Unknown binary message version is distinct from unsupported container version, codec and logical schema in Rust, and each maps to `UNSUPPORTED_SCHEMA`. Existing `UnsupportedContract` continues to map to `INVALID_SAMPLE`. `LegacyContract` emits every field, including `blink: null` for None, an array for fonts even when empty, all font fields, lowercase cursor phase, exact float types and original order. No `skip_serializing_if` or Value conversion is applied to that contract.

Sol medium review correction: zero snapshot grid dimensions map to `INVALID_SAMPLE`. Zero claimed or decoded image dimensions and image/grid disagreements retain `INVALID_IMAGE` through `DimensionMismatch`. Image dimensions or decoded allocation above explicit limits map to `RESOURCE_LIMIT`. This supersedes the earlier general statement about zero dimensions.

Sol medium accepted this digest, error-mapping and exact-byte approval sub-contract as an implementable design after the zero-dimension correction. Golden capture, binary implementation/tests, aggregate memory proof and the overall gate remain open.

## Proposed streaming digest projection

This proposal supersedes using upstream snapshot serialization to construct a JSON Value if independently approved. The current upstream serializer clones snapshot fields and the Value plus output Vec require additional allocations. Instead private borrowed serializers stream through serde_json's compact serializer into an infallible SHA-256 writer. They must reproduce the exact old bytes, not merely semantically equal JSON. Snapshot keys are emitted in recursively sorted Value order: `cells, cols, cursor, default_background, default_cursor, default_foreground, palette, rows, schema, scope, title, viewport_origin`. Cell keys are `bg, blink, bold, dim, fg, inverse, invisible, italic, link_id, link_uri, strike, text, underline, underline_color, width`. Cursor keys are `blink, col, color, in_capture, row, shape, visible`. Omitted metadata, arrays, nulls, enum and color representations retain old behavior. RGB hex is emitted from a fixed seven-byte stack buffer. The contract serializer retains original declaration order and actual float types; its font sequence streams borrowed wrappers.

The digest budget is separately defined as incremental allocation requests while borrowing an existing Sample. It excludes arbitrary caller-retained samples, input and other concurrent operations. Snapshot/contract serialization, hasher and fixed RGB buffers are intended to be stack-only. For an image, calculate the exact decoded base64 length with checked arithmetic, reserve once, decode into that buffer, call the reviewed PNG helper borrowing it, hash RGBA, then drop all image work before returning a 64-byte hex digest. The digest-phase proposed peak is `max(64, P + PngPeak(P,w,h) + 64)`, plus audited errors and stack, where P is exact decoded PNG bytes and PngPeak includes RGBA and every PNG allocation. Check the phase budget before reserves, map reserve failure to a typed resource error with source, and preserve `DigestProjection` source chaining. Confirm pinned serde_json's streaming formatter does not allocate input-dependent memory, exact upstream projection mappings and all simultaneous lifetimes before accepting this design. Golden byte fixtures, full state digests, signed zero, optionals, escaping and error cases must establish equivalence. Neither this term nor a numeric cap is approved yet.

Caution: public `Sample::state` and `Sample::with_pixels` can create in-memory samples without passing the file-size cap, so a digest budget cannot assume PNG bytes P or all snapshot strings are <=64 MiB. Use actual checked sizes and do not introduce a new smaller public-domain limit. A dynamic incremental-work bound may be needed; it must account for caller-retained values separately. The current workspace feature tree for serde_json 1.0.154 contains default and std, without `preserve_order`; this does not establish downstream feature unification behavior. The private sorted serializer must be reviewed against that distinction and old actual projection bytes. Source proof and tests remain open.

## Feature-unification and in-memory correction

The first streaming proposal was rejected because the old snapshot JSON Value uses declaration/insertion order when another dependency enables serde_json `preserve_order`. Reproduce the active old behavior for both configurations. A proposed small input-independent `serde_json::Map` probe inserts `b` then `a` and selects static serializers by observed first key. Do not iterate this map to produce canonical output; both resulting orders are explicit. Bound the probe's actual requests. With preserve_order, after removing final metadata the snapshot keys are `schema, cols, rows, scope, viewport_origin, cells, palette, default_foreground, default_background, default_cursor, cursor, title`; cell keys are `text, width, fg, bg, bold, dim, italic, inverse, invisible, strike, blink, underline, underline_color, link_uri, link_id`; cursor keys are `col, row, in_capture, visible, shape, color, blink`. The sorted orders remain as above. Contract serialization remains declaration order in both configurations. Test the old and new outputs with both real Cargo feature graphs. The probe's allocation and source mapping need independent review.

Use an incremental per-call digest allocation allowance computed from the Sample's actual decoded base64 length P, actual dimensions and the source-reviewed PNG peak, in checked wide arithmetic. It must not reuse the binary decoder's fixed budget or assume P <=64 MiB. Charge newly requested layouts before each operation, distinguish already-held Sample and other caller allocations, and reject only existing image limits, arithmetic/address-space overflow or actual reservation failure. The computed term includes decoded PNG, PNG internals and RGBA, output digest and error allocations. Exact PNG/error and probe terms remain under review. This policy is proposed; it does not yet prove full behavior or memory coverage.

For resource accounting, the later closed-source proposal supersedes the earlier arbitrary boxed-error types: codec source is a concrete `Box<ZstdError { code: usize }>` with static error-name display, resource source is limited to `Option<Box<png::DecodingError>>`, and reserve failure uses `Allocation { site: &'static str, requested: u64, source: TryReserveError }`. Target builds assert each required box request <=4096. Preserve source chains and classify all three as specified. This revised public error design needs independent review.

### Allocation-free order discriminator proposal

A source experiment identified a possible unpatched safe discriminator without constructing a serde_json Map. Under the pinned serde_json version, inherent `Map::swap_remove` exists only with `preserve_order`. Define a fallback trait method of that name on `Map<String, Value>` returning a zero-sized marker `Sorted`. Define a trait with `const PRESERVED` implemented as false for `Sorted` and true for `Option<Value>`. Pass the uncalled closure `|m| m.swap_remove("probe")` to a generic function that returns the associated const of its inferred result type. Inherent method precedence selects `Option<Value>` when preserve_order is active; the fallback selects `Sorted` otherwise. The closure is never executed, so it constructs no Map, keys, hasher or RNG. An actual local compile/run probe reported false and true under the two real feature graphs. This depends on pinned serde_json API shape and stable Rust method-resolution rules; preserve the exact probe, address any dead-code lint without hiding errors, independently review, and test both graphs. This proposal supersedes the allocating map probe if accepted.

Sol medium accepted the allocation-free order discriminator for exact serde_json 1.0.154, contingent on probing the same dependency instance, controlled method-resolution scope, fixing dead-code warnings narrowly, and comparing old/new bytes under both real feature graphs using sequential builds or separate targets. The exact serde_json version must be constrained in the relevant dependency boundary; a semver range alone does not make this method a stable feature-detection API. This verdict covers the discriminator only, not total digest/PNG allocation.

Digest image phase proposal, still unapproved: validate claimed dimensions in the existing order, compute/validate exact base64 decoded length P with checked arithmetic without a 64 MiB cap, reserve and decode once. Charge a proved P-dependent header allowance before constructing `png::Decoder<Cursor<&[u8]>>`. Read the actual header, then validate its dimensions before `read_info` and row/RGBA allocations; configure the separately reviewed nonrestrictive PNG counter. Preserve the original sequence of PNG decoding versus claimed/actual mismatch checks where needed to retain diagnostics. Rejecting mismatch directly from an early IHDR peek could change which error wins when later PNG data is corrupt. Reserve RGBA once, decode one frame, hash pixels and drop image work before creating the 64-byte result. Internal error mapping uses concrete bounded source types and avoids formatting input-derived values during construction. Prove the header allowance, base64 decoding semantics and selected PNG error precedence before adopting the dynamic formula.

Proposed header-stage incremental allowance is `P + Meta(P) + Deflate + Err`, charged before constructing the PNG decoder; this includes the 128-byte raw chunk vector and boxed fdeflate state/tables, while no row or transform allocation has occurred. After `read_header_info`, check actual dimension resource limits before `read_info`, then charge the full `P + Meta + Rows + Q + Deflate + Transform + Err` allowance using actual header dimensions. Keep the actual claimed-versus-decoded mismatch check after full decode to preserve existing error precedence; malformed header errors remain decoder errors. `png::DecodingError` and fdeflate error enum source audit found no retained input-sized strings; bound one concrete error box with a target assertion and do not route through an adapter that calls `to_string`. Pinned serde_json's compact serializer streams escaped strings and formats floats in stack buffers; private serializers and the hash writer must not invoke custom error or map-key paths. The 65,536-byte fixed error allowance and early-phase source coverage require independent review and instrumentation.

PNG helper must explicitly set `png::Transformations::EXPAND` before `read_info`, matching the old image wrapper; png's default IDENTITY is not equivalent for indexed+tRNS or RGB+tRNS. Checking actual header dimensions before `read_info` is required to bound row allocation and may change error precedence for malformed inputs with both oversized dimensions and later corruption. Preserve the existing resource/image classifications; distinguish this malformed-input boundary from the unchanged digest of already validated samples. Verify the precedence in CLI tests and document it.

Sol medium accepted the streaming digest and dynamic incremental-budget design after the explicit EXPAND and error-precedence decisions. This does not establish implementation correctness, PNG compatibility, target assertions, old/new goldens under both feature graphs, allocation experiments or the aggregate decoder ledger.
