# Proposed implementation interfaces and test seam

These are additions to the previously reviewed contracts. Independent combined review is required before implementation dispatch.

Coordinator owns existing `sample.rs`, `lib.rs`, workspace manifests and lockfiles, CLI manifest, and cross-module wiring. Encoder/mapping worker C owns new `crates/tuiscotti/src/sample/wire/{mod.rs,generated.rs,map.rs,write.rs}`, schema/policy/descriptor and isolated `tools/schema-gen/`. Decoder worker D owns new `crates/tuiscotti/src/sample/{budget.rs,decode_error.rs,container.rs,png_decode.rs}` and the vendored PNG assertion patch. A digest worker owns new `sample/digest.rs`. CLI test worker owns new `crates/tuiscotti-cli/tests/compressed_binary.rs`, its helper directory and binary fixtures. All writers use separate worktrees. D supplies interface-only definitions first; coordinator reviews and distributes those signatures before C/D work against them. Shared existing files have one owner. Any missing decision or changed shared interface goes back to coordinator instead of being guessed.

Private boundary proposal:

```rust
fn scan_sample<'a>(bytes: &'a [u8], budget: &mut DecodeBudget) -> Result<ValidatedSample<'a>, DecodeError>;
fn map_sample(root: ValidatedSample<'_>, budget: &mut DecodeBudget) -> Result<Sample, DecodeError>;
fn decode_sample(bytes: &[u8]) -> Result<Sample, SampleError>;
fn encode_sample(sample: &Sample) -> Result<Vec<u8>, SampleError>;
```

Validated tokens have private fields and are created only by a successful full scan. They borrow the immutable decompressed buffer. Their typed getters and one-pass repeated iterators rescan validated spans without allocations or unsafe code. The scanner has a fixed 32-frame stack, generated presence/oneof state and cumulative counts. Generated descriptor and policy dispatch drive scanner, mapper and encoder. A trait requires one no-default handler per field/oneof alternative; ordinary singulars are visited once, repeated fields receive one encounter-order iterator, and only the selected oneof handler runs. The generated writer invokes all required handlers in canonical field order. Added fields must make both handwritten implementations fail compilation after regeneration.

`DecodeBudget` is a non-Clone private ledger with checked u64 requested-layout total and phase. It creates non-Clone opaque charge tokens only after verifying a request against the reviewed target-dependent envelope. Releasing consumes the token after the corresponding allocation is dropped. Native PNG and Zstandard internals are precharged as reviewed envelopes; do not double count their subterms. Scan computes L, C, F and PNG size before mapping. Precharge one domain envelope `L+128*C+64*F` and base64 term `4*ceil(P/3)`, then use one fallible exact reservation for each mapped collection/string and enforce its logical size independent of allocator capacity. Hold the message and input leases throughout mapping/PNG validation. Do not store one token per cell. Audit every allocation site and lifetime; a token alone cannot prove correct release. Digest uses its separate dynamic per-call accounting.

`DecodeError` separates `Format(BinaryFormatError)`, resource, inline allocation failure, unsupported container u16, message u32, codec u16, logical schema and existing domain SampleError. Mapping to SampleError retains sources and classifications without input formatting or filesystem I/O conversion. `BinaryFormatError::Wire` must carry offset, static detail and a bounded field path. The proposed public opaque `WirePath` has a fixed 32-part array of static names, repeated indices and numeric unknown tags, private fields and bounded formatting. This extends the earlier error contract and requires explicit review. Header/frame offsets refer to file bytes; wire offsets to decompressed message bytes. Upstream row/column to cell index uses checked arithmetic.

Private projection test seam: factor the actual private snapshot/contract digest writer into functions accepting `std::io::Write` and call those from both state_digest and `#[cfg(test)]` child tests. Compare output with pre-change component projection fixtures, not JSON Sample input. The explicit command `cargo nextest run -p tuiscotti --lib --locked --offline` runs private library tests despite `[lib] test=false`: a temporary probe test passed on the old checkout. Default workspace nextest does not substitute for this lane. Exercise both serde_json feature graphs with isolated target directories and an isolated copied workspace or host, without adding workspace features; demonstrate the target unit tests actually run and the intended same serde_json instance/features resolve.

Malformed and binary golden seam: CLI integration tests independently assemble wire bytes with a small test-only key/varint/length/fixed encoder and exact public 32-byte header, then compress arbitrary payloads using pinned test-only Zstandard. Mutate lengths, descriptors, fields and frames without exposing production wire types or adding a sample reader. Compare actual CLI/library behavior, source classifications, exact candidate/evidence/installed bytes and baseline no-write behavior. Store a literal independently checked raw protobuf golden and replay all recorded TSV contract, pixel, equivalent-RGBA, mismatch precedence, signed-zero and approval summary cases. Full container goldens await measured encoder settings and cross-platform proof. Report indexing reads result JSON, not a sample, and retains its separate contract.

Writer boundary: generated traversal offers checked `encoded_len(sample,png_len)` and `encode_into(sample,png,&mut ProtoSink)`, returning typed `EncodeError` directly. The count pass uses checked u64, stops at 64 MiB, and reports unknown claim rather than a fabricated final length on overflow/early stop. Reserve exactly once, append within predicted length and check final equality. Decode canonical base64 once for pixel sample; retain exact PNG bytes and do not rerender. Then a bounded file sink reserves at most 64 MiB, keeps 32 bytes for header, streams fixed 65536-byte input/output chunks via reviewed Zstandard calls, enforces payload <=64 MiB-32 and uses a one-byte completion probe. Finish checksum before declaring success; fill the header and expose only complete bytes. `EncodeError` distinguishes limit, `TryReserveError` allocation, concrete Zstd error and internal invariant; maps to SampleError preserving typed sources and classifications. CCtx creation failure needs a concrete allocation-without-source variant. Encoder context memory and selected compression level remain benchmark and implementation-validation gates, not claims made by decoder budget.

Writer error decisions: `EncodeError::ContextAllocation { site: &'static str }` represents `CCtx::try_create() == None` without inventing a `TryReserveError`; map it to a public non-exhaustive `SampleError::CodecAllocation { site: &'static str }` and `RESOURCE_LIMIT`, with no source. `EncodeError::Invariant { detail: &'static str }` maps to `SampleError::EncodeInvariant { detail: &'static str }` and `INVALID_SAMPLE`. `EncodeError::Codec { source: ZstdError }` maps to `SampleError::EncodeCodec { source: ZstdError }`, preserving source and `INVALID_SAMPLE`. Existing validation and filesystem errors keep their established mappings. These variants carry no attacker-controlled owned text.

Independent narrow review accepted these necessary refinements: `DecodeBudget::release` returns a typed `Result` and validates originating ledger identity and underflow before changing totals or high-water state. A failure consumes the token, preserves accounting and aborts the decode; it must never silently release or panic. Phase transitions are checked, with state-only completion at Mapping. `WirePath` must allow up to 96 bounded inline components so a 32-message path can include field, index and numeric tag per level. The concrete safe, portable ledger-identity mechanism and its allocation accounting remain to be reviewed before integrating the modules. Required tests cover wrong-ledger release, underflow, legal/illegal phases, high-water tracking, maximum-depth paths and lifetimes on all exits.

Sol medium accepted wrong-ledger identity via a private `Rc<()>` owned by each budget and cloned into non-Clone envelope tokens. Charge one target-derived `RcInner<()>` requested layout (pinned Rust uses `repr(C,align(2))` two `Cell<usize>` and unit) while the identity is alive. `Rc::ptr_eq` rejects another ledger without mutation; failure consumes the token and aborts decode. Bound simultaneous envelope tokens at 16 for the fixed orchestration to prevent refcount overflow; this is not a data-dependent sample limit. The ledger stays local to synchronous decode and never escapes publicly. Actual target layout, lifecycle and wrong-ledger behavior need tests and allocation instrumentation.

Container implementation refinement awaiting implementation risk review: `decode_container(input: &[u8], budget: &mut DecodeBudget) -> Result<DecodedMessage, DecodeError>` returns a private `DecodedMessage { bytes: Vec<u8>, charge: Charge }`. The caller holds the input charge and enters Codec; the function precharges the reviewed context/workspace envelopes, performs strict decoding, drops the context before releasing its envelope, enters Scan, and returns bytes with their message charge. The caller drops bytes before releasing the message charge. `DCtx::try_create() == None` is `DecodeError::ContextAllocation { site: &'static str }`, mapped to `RESOURCE_LIMIT` without inventing a source. The actual vendored C context-size assertion and build feature/source enforcement remain unverified integration requirements.

PNG helper integration decision, awaiting C/D/E risk review: define a private `PngBudget` trait with associated non-Clone token and fallible `charge(site, bytes)` / `release(token)` methods returning `SampleError`. A DecodeBudget adapter maps its internal errors through the coordinator-owned conversion; a separate dynamic digest-budget adapter uses the same trait without the binary intake cap. The helper returns private `PngPixels<Token> { width, height, rgba: Vec<u8>, charge }`; caller drops RGBA before releasing that token, helper drops decoder before releasing its internal envelopes. Caller performs the existing claimed-dimension precheck and compares claimed versus actual after decode. Helper checks actual header dimension/resource limits before read_info, sets EXPAND, and converts png errors into the existing `PngDecode { source: image::ImageError }` chain or reviewed PngInvalid/resource variants without eagerly formatting sources. This addition needs independent review and real lifetime/adapter tests.

PNG error conversion refinement: Format and Parameter are wrapped as `image::error::DecodingError` retaining the concrete `png::DecodingError` source without eager `to_string`; IoError maps directly. LimitsExceeded maps to `SampleError::ResourceLimit { resource: &'static str, claimed: None, limit: configured_png_counter, source: Some(Box<png::DecodingError>) }`. The Parameter wrapper changes its source representation but retains `INVALID_IMAGE` classification and diagnostics; validate this separately. The refinement is pending C/D/E review.

## Scanner and writer contract refinement

The first generator draft exposed constructible `Validated* { pub bytes }` wrappers and did not emit executable scan/write orchestration. Those artifacts do not meet the reviewed design. All generated scanner/token/accessor code belongs to one private module, potentially assembled using `include!` shards. Its private `Span<'a>` contains borrowed immutable bytes and absolute start; `ValidatedSample<'a>` and every nested token have private fields and no sibling-visible constructors. Only successful `scan_sample` creates a root; only generated getters and iterators derive children from a validated span. Typed getters return `Result` rather than using unchecked operations or `unreachable!`; repeated fields use private-state, single-pass iterators yielding `Result<ValidatedItem, DecodeError>` in encounter order without a Vec or field index. Color decode is a closed validated union. Do not pass validated decoder tokens into encoder adapters.

Generate an exhaustive MessageKind/tag match with an explicit `[Option<Frame>; 32]` stack. A frame stores span/cursor, seen and oneof masks, cumulative repeated counts and generated cross-field accumulators. Check key/wire, required presence, duplicate/oneof, scalar range/UTF-8, child span, lengths and local/cross-field constraints; refuse depth 33 before pushing. On pop, check required masks and propagate checked summaries. Accumulate L/C/F/P budget claims before owned allocation. Getter and iterator rescans are fallible and bounded, use no unsafe, and cannot turn an internal codegen inconsistency into a panic. Decode traits have mandatory distinct methods per field and real oneof branch; generated visitors call required/optional handlers exactly once and pass repeated fields as a single iterator.

Writer uses private typed `ProtoSink { fn position(&self) -> u64; fn put(&mut self, bytes: &[u8]) -> Result<(), SampleError>; }`, with CountSink checked against 64 MiB and VecSink restricted to pre-reserved counted logical length. `put_varint`, `put_key` and `put_bytes` write canonical shortest encodings, checked keys and stack little-endian float bits. Generated `emit_sample<S: ProtoSink,E: EncodeSample>` emits ascending tags; nested messages use the same generated child emitter with a CountSink to compute their length, then emit and verify exact written length. Typed `Encode*` traits use GAT child adapter and iterator types borrowed from domain adapters in `write.rs`; every descriptor field and oneof branch has its own mandatory method, no defaults or validated-token inputs. Generated oneof emission checks exactly one branch. Count and write share the same immutable Sample and adapter; a count mismatch returns the typed invariant error and discards the output.

The image adapter borrows an exactly reserved buffer decoded once from the existing canonical base64 view for both passes; drop it after emission. Coordinator owns bounded file sink/Zstandard integration and preserves typed errors without converting to generic I/O. Writer-specific peak and encoder-context bounds are not covered by the decoder ledger and remain measured/reviewed work. This refinement needs independent review before generator implementation continues.

`put_bytes` means raw byte emission only; generated field code writes the key and checked length prefix explicitly. CountSink enforces the 64 MiB root limit and VecSink enforces its pre-counted root/child bounds. Cross-field summary types and L/C/F/P accounting must be generated from the accepted policy, not approximated by generic counters. Writer PNG scratch and encoder workspace need independent allocation and compatibility validation; they are not charged to the decoder budget.

Generator location correction: alint 0.21.0 rejects first-party Rust under `tools/`. Place the isolated non-shipping generator at `crates/schema-gen/`, with its own `[workspace]` and lockfile, and do not add it to root workspace members or production dependencies. This keeps two shipping workspace crates and satisfies the repository source-location rule without weakening it. Update all generation commands and verify root workspace membership.

Container encoder handoff: shared private `sample/decode_error.rs::EncodeError` has `Limit { resource: &'static str, claimed: Option<u64>, limit: u64 }`, `Allocation { site: &'static str, requested: u64, source: TryReserveError }`, `ContextAllocation { site: &'static str }`, `Codec { source: ZstdError }`, and `Invariant { detail: &'static str }`. `encode_container(message: &[u8], level: i32) -> Result<Vec<u8>, EncodeError>` requires an explicit level so no unmeasured final setting is hardcoded. Coordinator converts to SampleError using the reviewed mappings. Schema writer sinks already return SampleError directly. This refinement needs C/D/E risk review and actual encoder resource measurements.

Writer adapter clarification: decode the canonical base64 PNG once into one exactly reserved scratch buffer before constructing the image adapter. `EncodeImage::png(&self) -> &[u8]` borrows that same buffer for both count and write passes; `CountSink::put` only counts the slice length. The count pass takes the same immutable adapter rather than a separate png-length-only interface. Drop the scratch only after both passes. This introduces neither a new sink method nor a second base64 decode.

Velnor discovery: a disposable Velnor 0.1.58 comparison found that `crates/schema-gen/` adds ten automatic Rust tasks even though it is a separate workspace. `discovery.exclude = ["crates/schema-gen/**"]` restored exactly the original 20 task IDs in that test. The main configuration must be changed through `.velnor/config.toml` and regenerated once the tool exists. An exclusion is not a verification gate; the required offline schema regeneration check needs an explicit supported task/check and must be validated on Velnor 0.1.73.

Post-review output accounting: retain the mapped domain and base64 envelope charge tokens in fixed inline budget slots. A consuming terminal `finish` checks that all non-output leases are released, leaves retained output charges included in the high-water accounting, and consumes the ledger without claiming the returned `Sample` allocations were dropped. Reject wrong-ledger tokens and unexpected live charges; no subsequent charged decode work may occur after finish. This repairs the review finding and requires focused ledger tests and independent integrated re-review.

Independent Sol medium review accepted a compact schema-proved, allocation-free production WirePath in principle, superseding the 96-component inline representation only when descriptor generation proves complete equivalent coverage. It stores at most five generated field IDs, a full-width optional u64 repeated index and insertion position, and optional terminal u32 unknown tag; validate all reachable paths (including final repeated scalars, oneofs, missing fields, unknown tags), reject cycles, >5 fields, >1 repeated segment, or field-ID overflow. All append operations must be checked and preserve state on failure. Pop order must retain an enclosing repeated index until its own index pop. The scanner still enforces 32 frames; synthetic depth tests may use a separate generic test path, but cannot substitute for production diagnostic tests. Required tests cover deepest failures/missing/unknown, sibling transitions, roots, offsets, max u64 index/u32 tag, failed append, and generator rejection fixtures; measure target enum sizes. This is design acceptance only, not implementation approval.
