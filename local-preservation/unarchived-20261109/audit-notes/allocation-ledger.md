## Metadata source proof proposed for review

The raw chunk vector begins at 128 bytes and grows only when full via exact reserve; current plus old requested layouts are charged by `3*max(128,P)` (png 0.18.1 `decoder/stream.rs:603,767-794`). Retained cloned ancillary payloads are disjoint and total at most P, including swallowed malformed chunk paths and original capacities before truncation. ## Aggregate candidate, not yet accepted

The bound starts at successful bounded read, includes the input allocation and decode failure construction, and excludes file-open/read-I/O diagnostics, whose full caller path must be accounted separately without a new path-length limit. `from_bytes` borrows input but conservatively charges its actual size; `from_file` can reserve at most 64 MiB plus one byte to detect oversize without trusting file metadata. Never add a blanket 64-bit target restriction.

The proposed exact-reserved domain term is `D=L+128*C+64*F`, where L is the sum of disjoint copied field payload bytes (<=64 MiB), C <=1,000,000 cells and F <= floor(M/2) font messages. Do not cap metadata, fonts or strings below the format's existing message limit.

## Aggregate independent review and correction in progress

Sol medium rejected the aggregate sub-contract. The old `E=16*M+1 MiB` undercounts a reproducible long-string error: with a 2,000,000-byte DEL platform key the old suffix and growing diagnostic can request 36,603,016 bytes concurrently while E is at most 33,848,576. See `/tmp/tuiscotti-error-budget-probe.rs`. Its independently checked arithmetic otherwise matched the earlier phase sums.

A replacement candidate is `E=32*M+65,536`, based on `E_gate(p)=max(32,p+8)+3*max(4096,10*p+4096)` for the existing diagnostic and one additional M-sized clone, with checked arithmetic. Pinned Rust Debug escaping emits at most ten bytes per scalar, scalar count is at most input UTF-8 bytes, and pinned RawVec growth has the documented doubling recurrence. This still needs an exhaustive actual error-site and lifetime proof. Corrected provisional PNG/domain maximum is 19,301,445,335 bytes, not a measured peak or approved budget.

Proposed read enforcement: `from_bytes` rejects lengths above 64 MiB and borrows input. `from_file` reserves/resizes once to 64 MiB plus one byte, reads only into the remaining initialized slice until EOF/full, retries Interrupted, and rejects when the extra byte is present; never rely on metadata length or `read_to_end` growth. Preflight header and expanded length before sink allocation. The decoder reserves exactly the declared expanded length once, uses fixed 65,536-byte scratch, checks each output length before append and probes one extra byte after reaching the declared length. Drop codec context before mapping. Exact reservation failures need a typed resource mapping. File-open/read-I/O diagnostics have a separate path-dependent accounting boundary that preserves the full caller path; the successful-read decoder budget includes its input allocation.

The state-digest operation has a separate unresolved allocation bound and enforcement sequence. The decode budget must not be represented as covering later digest work or simultaneously retained candidates and baselines.

Proposed reservation failure variant: `SampleError::Allocation { site: &'static str, requested: u64, source: std::collections::TryReserveError }`, source retained inline and mapped to `RESOURCE_LIMIT`. It distinguishes allocator refusal from an observed policy-limit violation. Compute/check sizes before reserving and do not rely on unstable `TryReserveError::kind`. PNG/fdeflate internals remain subject to the separate requested-layout proof; ambient OOM recovery is not promised.

### Error and target refinements for review

Use closed bounded error sources. `Allocation { site, requested, source: TryReserveError }` stores the reserve failure inline. Binary codec source is one concrete `Box<ZstdError { code: usize }>` whose display uses static upstream error names, with a target assertion that its request is <=4096. PNG limit errors retain one concrete `Box<png::DecodingError>` with the same size assertion. Scanner paths use at most 32 inline static-name/index entries; binary errors carry static details, offsets and scalars, not formatted attacker values. Unknown-schema errors clone at most one field <=M. Domain constructors use direct color enums so their allocated `InvalidColor` branch is unreachable. Do not eagerly format sources or duplicate arbitrary input. Under those implementation constraints, the proposed `32*M+65536` error allowance covers the first failing branch, the old gate formatter and one simultaneous M-sized clone, with fixed remainder for bounded source boxes and details. The actual implementation and every conversion still require audit.

For target-provided `OS` and `ARCH` names, avoid silently narrowing target support. Let `r=checked(OS.len()+1+ARCH.len())` and `E_target=2*max(8,r)+max(32,r+8)+3*max(88,10*r+296)+8192`. Account this separate checked target-dependent term. A literal 32 GiB fixed bound for arbitrary custom target strings is not proved; the unconditional proposal is `max(32 GiB, base + E_target)` with target-specific assertions and checked arithmetic, while reporting actual supported-target bounds. This supersedes an unconditional fixed-32-GiB claim. Validate all target sizes without introducing a target-pointer-width restriction.

A failed open can construct a path-dependent diagnostic before input allocation. A read-I/O failure may occur while the 64 MiB+1 input buffer remains allocated, so account `I + E_io` for that phase and retain the underlying I/O source. Do not say every I/O failure occurs before the buffer exists. Preserve full caller path information without an arbitrary new path limit.
