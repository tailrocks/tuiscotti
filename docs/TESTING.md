# Tests and CI

Two shipping crates, a functional suite, other CLI integration suites,
and private library tests: `nextest` runs all default test targets in
the workspace. The library
tests include the embedded PNG implementation and sample wire and
validation tests; the CLI suite exercises the shipped binary and the
public library API end to end through real files and real processes.
The maintained example (`crates/tuiscotti/examples/hello.rs`, walked
through in [FIRST-SUCCESS.md](FIRST-SUCCESS.md)) is the only example
target. Retired suites are recorded under "Result vintages" as history
only.

## Layout

| Location | Suites (tests at HEAD) |
|---|---|
| `crates/tuiscotti-cli/tests/` | `functional`, `compressed_binary`, `compressed_oracle`, `repository_policy`, and `schema_generator` integration suites |

| `crates/tuiscotti-cli/src/` | no tests |

## The functional suite

| Test | Proves |
|---|---|
| `live_workflow` | A user captures a real terminal view from an in-memory Ratatui buffer, compares it, approves it, and reports on it: missing → accept → pass → changed → render (PNG decoding and dimensions, embedded-HTML page with markers) → indexed report with a report filename check. |
| `invalid_input` | Malformed arguments, corrupt samples, oversize input, and unsupported output extensions fail with the documented exit codes and error codes and never create or replace a baseline. |
| `ci_refuses_approval` | A set `CI` variable (empty, `false`, `true`) refuses approval without touching baselines; an unset `CI` approves. |
| `closed_stdout` | A closed output pipe preserves the operation result, and nothing panics. |

The standalone `repository_policy` suite checks that workspace and crate
manifests do not declare direct PTY or terminal-engine dependencies. It
also checks dependency parsing against temporary manifests.

The suite runs the shipped CLI binary in fresh temporary stores. It checks selected exit codes and JSON fields, approved sample bytes, PNG decoding and dimensions, HTML markers, and the report filename in the index.

## Running the suite

Every command below works from a clean checkout: the
`tuiscotti-tui-test` dependency is a plain crates.io release (`0.2.1`,
locked in `Cargo.lock`), so no untracked `.cargo/config.toml`,
`--config` flag, `[patch.crates-io]` entry, or extra registry access
is needed (`cargo fetch --locked` warms the cache for `--offline`
builds):

```sh
cargo nextest run --workspace --locked --offline
cargo nextest run --workspace --locked --offline --no-default-features
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked --offline -- -D warnings
cargo clippy --workspace --all-targets --locked --offline --no-default-features -- -D warnings
cargo clippy --workspace --all-targets --locked --offline --all-features -- -D warnings
```

On this machine, prefix every `cargo` invocation with a `disk-check`
probe and run it through `rust-build-guard -- mise exec -- cargo …`
(per `docs/migration/decisions.md`, D-GUARD-1); the bare commands above
are what the guard executes.

Neither workspace crate defines cargo features, so there is no
feature-combination matrix of our own; the default, `--no-default-features`,
and `--all-features` selections below exercise the same suite against
dependency feature unification. `nextest` runs the integration tests
(per repo policy, never plain `cargo test`). No task-local config file is
involved at any step.

Test discipline: explicit test IDs and explicit artifact roots.
Filesystem tests use temporary directories. No process-wide environment
mutation in parallel tests. No sleeps to hide races.

## CI wiring

CI is generated by Velnor Actions 0.1.73 (see the header of
`.github/workflows/ci.yml`): edit `.velnor/config.toml` and regenerate,
never hand-edit `.github/workflows/ci.yml` beyond what the generator
produces (its `Check generated files` job diffs the two).
The generator emits a `nextest` lane for each shipping crate under the
default and `no-default` configurations, plus `actionlint`, `plan`, and
the `required` merge gate. The default workspace nextest invocation
includes the library's private tests. The standalone schema generator
is excluded from workspace discovery; the CLI schema-generator
integration test runs its tests and checks generated-file freshness
with vendored protoc.

Gates run everywhere; approval happens only on a human workstation.
There is no flag or variable that approves — `ApprovalStore::accept`
and `tuiscotti accept` explicitly refuse when `CI` is set in the
environment (canonical rule: [SNAPSHOTS.md](SNAPSHOTS.md)).

Notes:

- Determinism: same frame + same profile + same vendored font
  bytes = byte-identical PNGs. Runners need no system fonts.
- Review flow for a red run: reproduce locally, inspect the candidate
  evidence, then run `tuiscotti accept` on your workstation and push
  the updated approved tree. Parallel jobs are safe: per-test files +
  atomic renames.
- Do not cache per-run evidence (`actual/` dirs, `report.html`)
  between runs.

## Link and doc checks

No automated link gate remains (`xtask` was deleted at D07). Before
pushing doc edits: list every relative link you touched and confirm the
target exists in the tree. Reviewers re-check links on doc diffs.
`README.md` fences are the contract — if you change a documented
behavior, update the README in the same commit.
