# R01 PR body: U06

Target title: `Add RGBA image comparison for pixel equality`
Target branch: `goal/u06-pixel-comparison` (base: upstream `main` at `f2760592ed00e90436f8c3bae124dab712eaecf8`)

## Problem

Callers cannot compare two decoded images without a baseline storage policy. The snapshot writer couples comparison to baseline files, so pure pixel equality (for example in approval re-rendering) has no API.

## Change

New pure function in `crates/tui-test/src/pixel.rs`:

```rust
pub fn compare_rgba(
    width_a: u32, height_a: u32, bytes_a: &[u8],
    width_b: u32, height_b: u32, bytes_b: &[u8],
) -> Result<PixelComparison, PixelError>
```

Exact equality of all four bytes per pixel (straight alpha, sRGB; zero alpha still compares RGB). Checked buffer arithmetic. Dimension mismatch returns a `Different`-style `Ok`, never a zero-difference success. Equal dimensions return changed-pixel count, compared-pixel count, smallest enclosing rectangle (`None` when empty), and a location-only difference image (magenta for changed, transparent black for equal). No baseline reads, writes, or approval. New result types only.

## Compatibility

Pure addition (`tui_test::pixel` module). No existing API touched. Rust-only, no FFI or binding changes. No MSRV change. No new dependencies (the `png` crate appears only as a dev-dependency for tests, reusing the workspace pin).
