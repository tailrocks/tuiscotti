# R01 PR body: U04

Target title: `Add explicit pinned-font rendering`
Target branch: `goal/u04-pinned-fonts` (parent: U03 branch `goal/u03-offline-rendering`, draft PR [#280](https://github.com/microsoft/tui-test/pull/280))

## Problem

Strict rendering reads system fonts and ambient font-selection variables, so two hosts can render the same snapshot to different pixels. There is no way to pin the exact font bytes, faces, and fallback order behind a versioned render contract.

## Change

New explicit `PinnedFontSet` in `crates/tui-test/src/render/pinned.rs` (font bytes plus face indices, explicit fallback order, style selection), wired into `SnapshotRenderOptions` as an opt-in field (default off; recorded system-font behavior unchanged):

```rust
pub struct PinnedFontSet { /* faces, fallback order, synthetic-style opt-in */ }
```

Under the pinned policy the renderer loads only the specified bytes — never system fonts, never ambient variables — through a dedicated `PinnedFontSystem` that resolves with `ttf-parser` directly instead of the system `fontdb` catalog. The used bytes are hashed; the evidence carries face index, style, and fallback order. Missing fonts, missing styled faces, and missing glyphs return typed errors with no host fallback, no replacement glyph, and no synthetic bold or italic unless the caller explicitly selects it. Cache identity (`PinnedCacheKey`) covers policy, font digests, face indices, style, fallback order, synthetic selection, scale, and every pixel-affecting raster setting. A versioned render contract reports renderer version, raster policy version (`pinned-v1`/`system-v1`), fonts, geometry, scale, palette digest, and cursor phase (strict images use the shown phase; blink intent stays in state).

## Compatibility

Additive only. `FontFamilies`, `RunOptions`, and other protected types are untouched; only goal-new types (`SnapshotRenderOptions`, `RenderedPng`, `RenderError`) are extended. System rendering shares identical code until the backend branch. Rust-only, no FFI or binding changes. No MSRV change. No new dependencies (shaping stays in a later change; multi-scalar sequences stop with typed `UnsupportedSequence`).

## Limits

Pinned rendering needs the `recording-raster` feature (raster work lives there). Shaping of combined glyphs arrives separately; until then a missing glyph in every pinned face is an error, never a silent substitution. No shared font cache exists yet; each strict render resolves from the specified bytes.

## Scope

The engineering requirement is host-independent fonts with render evidence. Grapheme shaping is a separate change.
