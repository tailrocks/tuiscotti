# R01 PR body: U07

Target title: `Add mode-aware programmatic input`
Target branch: `goal/u07-checked-input` (base: upstream `main` at `f2760592ed00e90436f8c3bae124dab712eaecf8`)

## Problem

Programmatic input has no mode checks. The legacy mouse path and raw writes send bytes whether or not the application requested the mode, so a test can pass while the application never asked for the input it received.

## Change

New checked methods on the session:

```rust
pub fn mouse_checked(&self, action: CheckedMouseAction) -> Result<(), CheckedInputError>
pub fn paste(&self, text: &str) -> Result<(), CheckedInputError>
pub fn focus(&self, focused: bool) -> Result<(), CheckedInputError>
```

Modes are read from one coherent terminal state and input goes through the ordered write path. Mouse actions are validated against active dimensions (history viewports rejected) and the click, drag, and motion support matrix: press and release need click support or better, pressed movement needs drag support, unpressed movement needs motion support. Encoding is SGR with DEC tracking modes 1000, 1002, and 1003 plus SGR encoding mode 1006; anything else returns `Unsupported`, and no SGR bytes are sent when the application chose a different encoding. Pasting wraps text in bracketed-paste markers only when the mode is enabled and rejects text containing an early terminator while markers are on. Focus reports go out only when focus events are enabled. New `#[non_exhaustive]` error and action types; raw and legacy methods are unchanged.

## Compatibility

Additive only. No changes to `Operation`, the CLI protocol, or generated bindings (`tui-test-bindgen -- --check` passes). Legacy mouse and raw write paths keep their behavior, pinned by tests. Rust-only. No MSRV change. No new dependencies.

## Limits

Only the SGR mouse encoding and DEC modes 1000, 1002, and 1003 are implemented; other negotiated encodings report `Unsupported` instead of guessing.

## Scope

The engineering requirement is input that obeys the terminal modes the application requested. Raw byte input and launch settings are separate changes.
