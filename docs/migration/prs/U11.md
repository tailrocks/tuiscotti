# R01 PR body: U11

Target title: `Keep explicit underline colors in terminal rendering`
Target branch: `goal/u11-underline-color` (parent: U03 branch `goal/u03-offline-rendering`, draft PR [#280](https://github.com/microsoft/tui-test/pull/280))

## Problem

The shared cell-paint conversion drops the captured underline color. Cells with an explicit underline color render with the foreground color instead, and indexed underline colors ignore the snapshot palette.

## Change

The one shared cell-paint conversion now carries the snapshot's underline color into both live and offline rendering. Indexed underline colors resolve through the snapshot palette; captured RGB values pass through directly; an explicit underline color wins, otherwise the foreground color is used (dimming and inverse swaps apply to the missing-color fallback as before, while an explicit color stays undimmed and wins). All underline-style values stay in canonical state. Recorded raster underline geometry is unchanged; no new double, curved, dotted, or dashed geometry. Pixels for cells without an explicit underline color are unchanged (run grouping and SVG bytes identical).

## Compatibility

No public API change (one `pub(crate)` paint field; all constructors internal). Live screenshot, recording, offline SVG and PNG, and diagnostics HTML all inherit the one rule. Rust-only, no FFI or binding changes. No MSRV change. No new dependencies.

## Limits

All underline styles still draw the recorded single bar; only `Single` is exercised in this suite because canonical equality already compares every style value.

## Scope

The engineering requirement is keeping captured underline colors through shared rendering. Font pinning and grapheme shaping stay out of this PR.
