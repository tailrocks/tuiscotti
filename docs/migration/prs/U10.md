# R01 PR body: U10

Target title: `Add configurable quiet waits and request cancellation`
Target branch: `goal/u10-request-waits` (parent: U02 branch `goal/u02-owned-snapshot`, draft PR [#278](https://github.com/microsoft/tui-test/pull/278))

## Problem

The only stability primitive is `Operation::WaitIdle` with fixed behavior. Callers cannot set a quiet interval or an overall timeout, cannot distinguish visual from byte quiet, and cannot cancel one request without touching the session:

```rust
// fixed idle wait, no per-request cancellation handle
```

## Change

New options type with private fields plus two session methods in `crates/tui-test/src/wait.rs`:

```rust
pub struct WaitQuietOptions { /* timeout, quiet interval, mode */ }
pub enum WaitQuietMode { Visual, Bytes }
impl Session {
    pub fn wait_quiet(&self, options: &WaitQuietOptions) -> Result<(), WaitError>
    pub fn wait_quiet_cancellable(&self, options: &WaitQuietOptions, cancelled: &dyn Fn() -> bool) -> Result<(), WaitError>
}
```

Defaults: 250 ms quiet interval, 5 s overall timeout. Zero timeout, zero quiet interval, and an interval longer than the timeout are rejected; equal deadlines return timeout. Visual-quiet compares raw active-screen snapshots (cells, dimensions, palette, defaults, cursor state, title) at 50 ms polls from request start; byte-quiet restarts on any nonempty PTY output read stamped on a monotonic clock. Success takes a last visual sample and checks cancellation first. Cancellation uses the engine's cancellable-execution vocabulary, composes the engine's pending-lifecycle preemption, never kills the child, never cancels another caller, and leaves the session usable. `Operation::WaitIdle` behavior is unchanged.

## Compatibility

Additive only. No changes to `RunOptions`, `OpenOptions`, `ExecutionContext`, `Cell`, or exhaustive enums. No new serialized operation variants. Rust-only, no FFI or binding changes. No MSRV change. No new dependencies.

## Limits

Sampling every 50 ms can miss a change between samples; the limit is documented and demonstrated, never presented as a frame boundary. Request-local timing tests cover the policy; wall-clock PTY tests stay bounded.

## Scope

The engineering requirement is settable stability criteria with per-request cancellation that keeps the session usable. Checked input modes and launch settings are separate changes.
