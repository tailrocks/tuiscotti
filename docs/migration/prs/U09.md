# R01 PR body: U09

Target title: `Add raw byte input for Rust sessions`
Target branch: `goal/u09-raw-bytes` (base: upstream `main` at `f2760592ed00e90436f8c3bae124dab712eaecf8`)

## Problem

Text input methods apply UTF-8 encoding. Protocol tests cannot send NUL bytes, escape sequences, or deliberately invalid UTF-8 through the ordered session input path.

## Change

New additive method on the public session (plus minimal engine/runtime forwarders):

```rust
pub fn write_bytes(&self, data: &[u8]) -> Result<(), TuiTestError>
```

It uses the recorded ordered PTY write path, keeps every byte, loops on partial writes, and retries interrupted writes. Closed-session writes return typed errors, never a panic. Text input methods are unchanged.

## Compatibility

Purely additive: three new methods, no signature or type changes, no new `Operation` variants (no serialized-protocol change). Rust-only, no FFI or binding changes. No MSRV change. No new dependencies.

## Tests

- `cargo fmt --all -- --check`: clean.
- `cargo clippy -p tui-test-rs --all-targets -- -D warnings`: clean.
- `cargo test -p tui-test-rs --test raw_bytes`: 4 passed, 0 failed (U09-A NUL, escapes, invalid UTF-8 round-trip byte-exact; U09-B 256 KiB payload complete and in order through a real PTY; U09-C closed-session writes return typed errors).
- `cargo test -p tui-test-rs --locked` (full): all suites green.
- The test file is `#![cfg(unix)]` (termios raw-mode fixture); Windows PTY byte behavior is unverified and recorded as unavailable.
- Platforms not available locally: Windows and Linux CI coverage pending.

## Limits

Post-exit (pre-close) writes map the kernel PTY error to `ErrorKind::Internal`; this is deterministic on Linux and macOS and unexercised elsewhere.

## Scope

The engineering requirement is raw byte input for protocol tests. Checked input modes (mouse, paste, focus) are a separate change.
