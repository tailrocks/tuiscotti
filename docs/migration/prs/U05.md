# R01 PR body: U05

Target title: `Render combined and wide cell text correctly`
Target branch: `goal/u05-graphemes` (parent: U04 branch `goal/u04-pinned-fonts`, draft PR [#284](https://github.com/microsoft/tui-test/pull/284))

## Problem

The raster renderer rejects any cell text with more than one Unicode scalar value (`unsupported_grapheme()`), so combining marks, CJK wide cells, and styled multi-scalar text cannot render at all.

```rust
// crates/tui-test/src/render/raster/draw.rs at f276059
unsupported_grapheme() // rejects e + U+0301, 東 + continuation, ...
```

## Change

One shaping path for cells, cursor repaint, and titles using `rustybuzz 0.20.1` (MIT, optional under `recording-raster`; shares the workspace `ttf-parser 0.25`, so no second parser enters the tree). Each cell grapheme shapes with one face selected per grapheme in pinned fallback order, so a combining sequence never divides across faces. Glyph positions stay within the snapshot's cell geometry; terminal column width is unchanged after shaping; cross-cell ligatures are impossible by construction (one `shape()` call per cell, ligatures off where column math needs it). Missing glyphs return typed `MissingGlyph` errors naming the scalar — never `.notdef` tofu, never a silent drop. Glyph evidence flows to `RenderEvidence::shaped_graphemes`. A 3,884-byte vendored Noto Sans JP subset (U+6771 plus `.notdef`, OFL-1.1 with `SOURCE` provenance) covers the CJK corpus case; tests read committed bytes, nothing fetches fonts at test time.

## Compatibility

Strictly additive. No signature, field, variant, or default changes. The `no-default-features` build is unchanged. Rust-only, no FFI or binding changes. No MSRV change (rustybuzz 0.20.1 is edition 2021, pure Rust, released against stable ~1.82; its manifest carries no `rust-version` key, so the fit is recorded rather than pinned). One new optional dependency.

## Limits

Styled CJK faces are not vendored, so styled CJK correctly yields typed `MissingFace`. No shaped-run cache exists (§19: no measurement requires one); shaping re-parses per cell, fine at test-grid scale.

## Scope

The engineering requirement is correct rendering of the mandatory grapheme corpus through the pinned path. No new shaping engine was written.
